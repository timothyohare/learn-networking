The big picture

Why split networking into layers?

Think of a building site

The electrician doesn't redesign the footings, and the concreter doesn't care what colour the walls are. Each trade relies on the one below it and serves the one above it, using agreed interfaces.

Network layers work the same way. Wi-Fi can be swapped for fibre without the web browser ever knowing.

Encapsulation = packing a shipment

Going down the stack, each layer puts the bundle from above into its own wrapper with a label (a header). At the other end, each layer removes only its own wrapper and passes the rest up.

Two kinds of address

IP address: the final destination, like a street address. MAC address: the next device on this cable or Wi-Fi, like "the depot down the road".

Illustrative valuesThe addresses come from ranges reserved for examples and documentation. Header sizes are the standard minimums (no optional extras).
Layer 7 · Application

What does the user actually want?

The browser writes an HTTP request. This is the real payload, the thing every other layer exists to deliver.

Unit is called
Data
GET / HTTP/1.1          ← "send me the home page"
Host: example.com       ← which website (one server hosts many)
User-Agent: Mozilla/5.0 ← which browser is asking
Accept: */*             ← any reply format is fine
                        ← blank line = end of request

75 bytes in total, counting the hidden line-break characters.

Analogy
The project brief: what the client wants delivered, written in their own words. It says nothing about trucks or roads.

Other Layer 7 protocols

DNS (names → IP addresses), SMTP/IMAP (email), SSH, FTP. Before this request, DNS already turned example.com into 198.51.100.80.

Honest simplificationTLS doesn't sit neatly in one OSI layer. It handles both the secure session (L5) and encryption (L6). Teaching it at L6 is the usual convention.
Layer 5 · Session

Open, keep and close the conversation

The session layer manages the dialogue: who's talking, whether it's still alive, and how it ends cleanly.

Unit is called
Data

① Open

TCP's 3-way handshake (SYN → SYN-ACK → ACK), then the TLS handshake: check the server's certificate and agree on encryption keys.

② Maintain

Remember the keys, keep the connection alive, and allow a dropped session to resume quickly.

③ Close

TLS sends close_notify, then TCP exchanges FIN messages so both sides agree it's over.

No new bytes at this layerLook at the bar: it's the same size as Layer 6. In the real internet (TCP/IP), Layers 5–7 are merged, so session work is done by TLS and TCP rather than a separate header.
Analogy
The contract period: mobilise and open the job, keep the site running day to day, then formally close it out.
OSI is a model, a way of thinking. Real protocols don't always fit its boxes.
Layer 4 · Transport

Deliver it reliably, to the right program

TCP adds a 20-byte header. Ports pick the program on each computer, and sequence numbers let missing or out-of-order pieces be fixed.

Analogy
The delivery docket: every pallet is numbered, the receiver signs for what arrived, and anything missing is re-sent. The port is the loading dock number at each building.

TCP vs UDP

UDP has an 8-byte header: just ports, length and checksum. No handshake, no re-sending. It's used where speed beats perfection: voice, video and DNS.

Sequence numbers shown are simplified "relative" values.

Lives here

IPv4, IPv6, ICMP (ping), and routers.

Analogy
One leg of the trip: the local driver between two neighbouring depots. Every leg gets a new driver and a new docket, but the street address on the box never changes.
MAC = next hop. IP = final destination. That split is the key to routing.

How did the laptop learn the router's MAC?

ARP broadcasts "who has 192.168.1.1?" and the router replies with its MAC. Switches live at this layer.

Layer 1 · Physical

Turn it into signals on the wire

The network card adds an 8-byte wake-up pattern and sends every bit as voltage, light or radio. 163 bytes is 1,304 bits, about 1.3 µs at 1 Gb/s.

Analogy
The road surface itself: the pavement, the lanes and the speed limit. It moves whatever is driven on it and doesn't care what's in the truck.

Media

Copper (Cat6): electrical pulses · Fibre: light pulses · Wi-Fi: radio waves (with its own frame format). Cables, connectors, hubs and repeaters live here.

Most real outages start here: unplugged cables, bad patch leads, weak Wi-Fi.

NAT may also change the source port, so the TCP checksum is updated too. Routers on the wider internet don't do NAT; they only do the MAC and TTL work.

At the server: unwrap bottom-up

  1. L1Hear the preamble, turn signals back into bits
  2. L2FCS OK? Dest MAC is mine? Strip the Ethernet wrapper
  3. L3Dest IP is mine? Protocol 6, so hand it to TCP
  4. L4Port 443, so give it to the web server. Put it in order, send an ACK
  5. L5Match it to the open TLS session
  6. L6Check the seal, decrypt, recover the 75 bytes
  7. L7Read GET / and send back the home page

The reply makes the same journey in reverse, with source and destination swapped.

Looking ahead

SD-WAN is encapsulation… again

An SD-WAN edge takes the whole IP packet we just built, encrypts it, and wraps it in a new outer IP header addressed to another office. This is a tunnel across the internet.

Why it matters

Each tunnelled packet carries ≈63 B of extra headers (IPsec with NAT traversal, typical case). A standard link carries at most 1,500 B per packet, so big packets can need splitting. That's an MTU problem, and it's very common in SD-WAN work.

What's "software-defined" about it?

A central controller decides which tunnel each application uses, e.g. video calls over fibre and backups over 4G. It reads L3–L7 info such as DSCP marks, ports and app signatures, plus live link quality.
